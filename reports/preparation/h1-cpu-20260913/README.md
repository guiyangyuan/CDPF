# H1 加权非目标蒸馏：CPU 实现与准备

工作始于2026-09-12，本机实现与最终测试于2026-09-13完成。本轮范围是实现和本机正确性验证，没有连接服务器、启动GPU或新增论文成绩。tiny CLIP合成输入上的CPU优化器步属于软件测试，不计入正式实验。

## 实现范围

- 新配置`TRAINER.TEXTCONSISTENCY.KD_LOSS_MODE`区分默认`full_kl`与`weighted_nckd`。
- 新项为`(1-q_y)·T²·KL(q_rest || p_rest)`，保留原非目标权重；教师KD分布和权重detach，在线教师CE照常训练。
- 默认全KL的有效数学操作保持原样，原架构、描述、采样、优化器和推理规则未因本对照修改。
- 损失身份进入训练记录、完整checkpoint和评估结果；重载与审计必须拒绝模式、温度或定义不匹配。旧权重继续配合冻结源码，源码SHA校验不放宽。

公式及入口说明见[损失对照文档](../../../docs/KD_LOSS_CONTROL.md)，原研究方案见[H1方案](../../diagnostics/kd-failure-20260912/NEXT_STEP.md)。本轮实现的是已知KL分解消融，不是确认的新算法贡献。

## 当前边界

旧`run_pilot.py`仍承载历史全KL/Base/Novel协议，没有将新模式接进旧队列。当前没有待运行GPU任务。未来需要独立准备H1的Base验证、固定描述均值融合与预设筛查；不能拿本机正确性测试充当效果实验。

后续预算仍为：最多一个DTD seed1历史全KL anchor，通过后再做三个数据集各seed1一个对照。配置和停止规则固定，不自动扩量，也不修改历史Novel/HM或论文。

- 完整测试：**153项通过**；较原128项新增25项测试，覆盖损失数学关系、真实tiny CLIP训练/重载及审计拒绝行为。最终本机套件耗时8.507秒，不是模型训练性能基准。
- 保存/重载：两种模式均在真实tiny CLIP架构和实际trainer/SGD上通过CPU训练步；student/teacher/ensemble三个分支重载输出一致，冻结CLIP参数不变，教师CE仍能更新教师分支。
- [历史logits独立核验](saved-logit-verification.json)：九组、1,500条记录，36组FP32/FP64默认损失值及师生梯度与冻结旧公式精确相等；18组FP64加权非目标项与“全KL减目标二元KL”的数值/学生梯度相符，最大误差分别2.22e-16和6.94e-18，目标KD梯度为0且教师KD梯度缺席。
- 数值核验先在核心实现版本执行；[最终核验收据](final-verification.json)进一步确认损失函数源码SHA在集成后完全不变，旧输入SHA均不变。不会把早期数学检查误写成后期新增实验。
- [三数据集配置核验](config-verification.json)：UCF101、DTD、Aircraft各检查全KL/加权非目标两份配置，共6份；除损失模式外完全相同，固定16-shot、20轮、T=2、KD=1、alpha=.5。本项只解析配置，没有加载数据或模型。

审查发现稀疏协议可以跳过损失身份校验，现已在`63ba4cf`修复：未知模式、新模式缺少必要协议字段、默认全KL记录夹带新模式身份均被拒绝；真正旧格式的全KL仍可审计。NaN/无穷大损失参数也提前拒绝。修复前29项针对性测试中10项失败，修复后29项和完整152项通过。

最终整体审查还发现稀疏现代全KL记录可接受不一致的温度；已在`ce6e7ee`修复。任何新版身份或显式模式标记均要求完整的预期KD权重与温度上下文，仅完全不含新版标记的旧格式记录保留稀疏兼容。针对性18项测试在修复前2项失败，修复后全部通过；最终完整153项通过。此前152项的核验快照单独保留，没有覆盖失败或较早结果。
