## 要回答的问题

同一组 DTD/Aircraft 模型中，KD0/KD1 的教师最终参数完全一致，学生改变；KD 对学生 Novel 的收益没有等量转化为最终融合收益。与此同时，已训练教师在 Novel 上低于固定描述均值。需要区分：学生改变是否有价值，以及该价值是否依赖推理时使用哪一种教师。

**唯一主要候选：KD1 学生与固定描述均值做 0.5 logits 融合。** 记为 S1+M。只把推理时的动态教师 T 换成 M，历史训练保持不变。其效果尚未跑出；不能把“换 M”写成已验证改进，也不能称为独有创新。它保留原方法训练成本；如果报告推理效率，需要另行实测。

## 固定交叉对照

所有设置统一用于三个数据集、三个种子；不按数据集、种子或 Base/Novel 身份切换设置。

- C：原 CoOp 学生。
- S0、S1：原完整方法的 KD0、KD1 学生。
- M：有效描述特征取均值后归一化的冻结描述分支，与已完成简单融合协议相同。
- T：原层级聚合加 MLP 教师。DTD/Aircraft 六对最终权重相同已核验；UCF 的 T0/T1 是否可合并必须先做同样核对，若不同，应分别保存，不能假设一致。

| 学生 | 与 M 融合 | 与 T 融合 |
|---|---|---|
| C | 已有强简单对照 C+M | 对照 C+T |
| S0 | 对照 S0+M | 原 KD0 完整推理 |
| S1 | 主要候选 S1+M | 原 KD1 完整推理 |

若 UCF 教师不同，两个 T 都完整交叉报告，主要候选和判断规则不变。不得事后选最优教师。先输出各独立分支，再计算全部组合；全部保留而非选出最高分的一格。

主分析固定 logits 算术均值，沿用相同 CLIP logit scale。另输出每格的等权概率均值作为固定诊断对照，softmax 温度为 1。它不改变主要候选；没有 alpha、温度、门控或描述筛选的搜索。不要把 logits 混合和概率混合的数值当作同一种分数。

优先比较 S1+M 对 S0+M（固定 M 后的 KD 影响）、S1+M 对 C+M（相对简单方法的价值）、S1+M 对 S1+T（固定学生后的推理教师影响）。这些是受控推理比较，仍不能单独证明训练时的梯度机制。

2. 强制 `split=val` 且 Base 类别；找不到验证集应报错，不能沿用现有运行入口可能退回 test 的行为。记录真实 loader 的类顺序、样本列表、transform 和各自哈希；检查实际训练/验证图片路径不相交。已匹配的 manifest 哈希不能代替该检查。
3. 校验 checkpoint、CLIP、描述模板、源码及实际参数加载；对 UCF 的 KD 教师做逐张量核对。重新映射类别时，logits 列顺序必须与标签一致。严禁将参数静默漏载后继续执行。
4. 编写针对性检查：缺验证集拒绝执行、样本/类顺序不一致拒绝合并、输入哈希不符拒绝加载、所有固定融合公式正确、不创建 optimizer、不修改 checkpoint、输出存在时拒绝覆盖。用小张量和真实元数据即可完成这些检查，无需训练。
5. 输出完整计划、输入收据和待执行清单；只有这些检查通过，才更新状态为“本机工具准备完成”。真实数据 loader 和 CUDA 若只能在服务器检查，应明确列为未完成项，不能直接写“GPU 就绪”。

## 之后一次推理应保存什么

范围固定为 UCF101、DTD、Aircraft × seed1/2/3，共 9 个 Base 验证案例，**新增训练数为 0**。使用第 20 epoch 旧权重与确定性评估 transform；同一案例所有分支读取同一批图片。

保存每张图的路径/样本 ID、标签、类顺序及 C、S0、S1、M、T 的完整 FP32 logits；教师不能合并时保存 T0/T1。记录实际前向精度，FP32 存储不代表模型一定以 FP32 计算。保留模型、样本、模板和源码哈希，禁止只保存最高分和 top-1。不用梯度，不拟合阈值。

导出后在 CPU 上计算：所有分支/组合的准确率、纠正与带错、错误重合、预测分歧、margin、NLL 和 Brier score。NLL/Brier 使用各分支对应概率且报告完整结果，不反过来拟合温度。本轮不声称测得梯度冲突；要验证它，需要另设训练侧实验。

运行成本取决于实际 loader/硬件，当前不承诺时长。优先复用同一案例的冻结图像/文本计算，计时需包含导出开销。GPU 推理不在本次已执行工作内，服务器继续关闭。

## 继续或停止的固定规则

这是节省实验预算的筛查规则，不是显著性检验，也不是论文录用标准。以下规则在补评估前固定，完整报告所有 seed，不根据结果再调整门槛。

| 检查 | 继续条件 | 不满足时 |
|---|---|---|
| 输入与推理正确性 | 全部哈希、实际划分、类顺序、完整加载及公式检查通过 | 停止导出，先修复；不以新分数覆盖历史记录 |
| Base 验证精度是否明显受损 | 对 C+M 的 logits、概率两个强对照分别比较：S1+M 的三个数据集等权平均准确率差均 ≥ 0；且每个数据集三种子均值下降均不超过 1.0 个百分点 | 停止把 S1+M 当作当前低成本改进方向，不靠调 alpha 或选 seed 挽回 |
| 固定 M 后 KD 是否有可观察价值 | S1+M 相对 S0+M 的三个数据集等权平均准确率差 > 0，同时完整呈现各数据集与种子差异 | 不以此声称 KD 增益；该精简候选不进入扩量训练 |
| 文献与机制边界 | 能提出区别于已有描述聚合/选择蒸馏/置信度融合的具体假设，并设计独立确认 | 仅保留为诊断/工程简化，不包装成论文新贡献 |

上述 Base 规则偏保守，可能排除“牺牲 Base 换 Novel”的方法，这是本项目有限预算下主动接受的取舍；不是证明失败候选没有任何用途。即使全部通过，也只表示值得进一步验证，不能声称 Novel/HM 提高。

## 关于独立确认

这三个数据集的测试成绩已经参与研究决策。Base 验证集属于训练见过的类别，不能称作“伪 Novel”，也不能只把同类测试图片换个名字当作未见类别。

若候选通过上述筛查，先固定方法与全部设置，再单列一个后续方案：使用未参与本次方法选择的数据集，或从训练类中提前划出类别、重新训练形成真正的类留出验证。后者需要新训练，不属于本次“零新增训练”检查。此前三个测试集的补评估可用于兼容性/事后机制解释，不能冒充独立确认。最终实验还需匹配接近方法的协议和实现，不能将 ADK 公式适配叫作官方复现。
