# 层级结构对照：固定协议与无卡准备

制定时间：2026-09-10。此前已观察到 UCF101 KD 对照结果；本批是后续诊断实验，不能称为尚未使用测试集的盲测。配置在本批训练前固定，保留全部结果，不按 Novel 成绩选择分组、seed 或 checkpoint。

## 要回答的问题

1. 在同等可训练参数量下，两级分组聚合是否仍优于全局平面聚合？
2. 原始描述顺序是否对层级结果有明显影响？改变分组后，结果是否稳定？

这批仅检验完整框架（含 MLP、KD）的结构价值。teacher/student/ensemble 分支分别报告，以观察结构变化和蒸馏的关联。它不单独证明所有模块有效，也不等同于相近方法比较或投稿条件已满足。

## 固定五个变体

| 变体 | 计算/分组 | 聚合器参数 | 含 prompt 的训练参数 |
|---|---|---:|---:|
| hierarchical_adapter | 原始连续顺序，两级聚合，同版参照 | 787,970 | 790,018 |
| flat_dual_adapter | 两个独立全局注意力头，权重平均后汇聚全部描述 | 787,970 | 790,018 |
| hierarchical_interleaved_adapter | 固定交错排序，再用原两级聚合 | 787,970 | 790,018 |
| hierarchical_shuffle17_adapter | 固定随机排列 17，再用原两级聚合 | 787,970 | 790,018 |
| hierarchical_shuffle29_adapter | 固定随机排列 29，再用原两级聚合 | 787,970 | 790,018 |

参数计数基于 ViT-B/16 的 512 维特征：4 个 512→128 投影（含 bias）共 262,656，2 个温度，两个 512→512 MLP 层共 525,312，prompt 为 4×512=2,048。两套全局注意力都实际参加前向/反向，没有填充无用参数。层级和平面双头使用同样的参数名称、形状和初始化顺序，计算结构不同。**相同参数量不表示 FLOPs 或延迟完全相同**；GPU 批次需记录时间和显存。

平面双头定义：每个头在全部有效描述上计算 softmax；两个头的权重各占 0.5；加权得到文本向量后做一次归一化。没有组内/组间池化。此次对照的多样性损失固定为 0。

顺序变换在原始文本选择、token 去重和冻结 CLIP 编码之后进行，只置换有效向量，padding 和 mask 的位置保持不变，不添加/删除描述。设有效描述数为 V、组数 G=4：连续顺序为 0…V−1；交错顺序按 `(原位置 mod G, 原位置整除 G)` 排序（20 条时为 0,4,8,12,16,1,5,…）。随机排列使用独立 `random.Random(17/29)`；同样的 V 使用相同排列，训练 seed 1/2/3 不决定分组。每个 epoch 不重新洗牌。这些都是位置分组，不是语义分组。

## 训练与评估

- UCF101，固定 Zhou 划分，Base 51 类、Novel 50 类，每 Base 类 16-shot。
- ViT-B/16，FP32，20 epochs，batch 16，seed 1/2/3，N_CTX=4，N_VIEWS=20，N_GROUPS=4。
- 与原完整方法相同：KD=1、温度=2，teacher CE=1，contrastive=0、diversity=0、ensemble alpha=0.5。
- 原结构也重跑，以相同源码版本作参照；旧模型留在旧 release 和旧输出目录中。默认计算回归检查通过不等于新的 GPU 结果已复现。
- 总计 15 次正式训练、90 次独立重载评估；Base/Novel 和三个分支使用该模型同一个第 20 epoch checkpoint。训练过程内存中的 test 输出不算独立评估。
- 完整模式入口禁止改变数据集、seed 列表、轮数、KD 或设备。单轮 GPU 冒烟使用普通 `--variants` 入口、独立目录，不计入正式结果。

汇总报告必须包含三个 seed 的 Base/Novel/HM、均值与样本标准差，以及每个对照相对原结构的配对差值。两种随机分组分别报告，并列出全部六次运行；不能选择更好的一组当最终方法。三种子不足以单凭均值增益声称统计显著。

若容量匹配后层级优势消失，应明确承认原差异可能主要来自容量/结构耦合；若分组改变使结果大幅波动，应降低关于层级稳定性的表述。无论结论正负，保存该批数据，不对 Novel 成绩反复调参。之后按固定协议开展 DTD/Aircraft 和相近方法比较。

## 身份、审计与旧版兼容

新 checkpoint 的模型签名为 format 2，包含 `view_order/order_seed/order_version`。实际每类描述数、排列和 SHA256 记录于 `run_manifest.json` 和评估 `metrics.json`；Base/Novel 类别不同，因此分别验证各自排列和一致的模型签名。汇总核查配置、参数量、所有分支同一 checkpoint、实际 checkpoint 文件哈希、同 seed 同采样以及不同对照的描述成员一致。

旧 checkpoint 因源码哈希和签名不同，必须继续在旧 release 中读取；不绕过校验强行混用。旧结果 JSON 仍可用旧协议汇总。源代码新增默认字段，但旧六变体的默认数值计算保持不变。模型权重、数据、SSH 凭据不进入 Git。

## 开卡后的顺序

1. 核实当前 SSH、CUDA、内存、磁盘、新 release 的源码 SHA256，确认没有运行中的训练。
2. 在新输出目录对五个变体各做一轮 GPU 冒烟和独立重载，记录耗时/显存；检查签名、分组和参数量。无卡准备只验证 CPU 小尺寸真实 CLIP 架构，未验证本版本完整预训练模型的 GPU 执行。
3. 冒烟通过后，生成并核对固定命令计划，运行正式批次。命令见准备报告；运行目录必须是新的。
4. 跑完汇总全部结果、检查原结构是否复现历史数值，再保存完整权重/日志到本机并校验。更新 PROJECT_STATUS.md、报告与 GitHub。

核心命令（在已激活新 release 内）：

```bash
python scripts/repro/run_pilot.py --data-root /root/autodl-tmp/textconsistency/data --output-root /root/autodl-tmp/textconsistency/runs/ucf101-structure-v1 --structure-study --seeds 1 2 3 --plan-only
```

正式运行时移除 `--plan-only`；这一步等待用户开卡。已存在输出目录会被拒绝，失败后先审计已有日志和 checkpoint，再决定恢复步骤，不能直接覆盖重跑。
